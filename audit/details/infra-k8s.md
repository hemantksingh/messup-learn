## Cross-file observations

- **Checklist items from the assignment that are absent, not wrong.** None of the seven files contain YAML manifests, so no `extensions/v1beta1`/`networking.k8s.io/v1beta1` Ingress, `batch/v1beta1` CronJob or `PodSecurityPolicy` strings exist to flag. The risk is omission: Overview.md and Kubernetes Security.md predate PSP removal (1.25), dockershim removal (1.24), Gateway API GA (Oct 2023) and the ingress-nginx retirement (Mar 2026) and mention none of them. Docker Desktop licensing appears only implicitly via Overview.md line 20 ("docker for windows or docker for mac"). Docker Compose v1 vs v2 appears only at Docker.md line 60 (`docker-compose up`) and in `Cheat sheets/Ubuntu.md` line 17 (`apt-get install ... docker-compose`), both v1 syntax.
- **Highest-impact stale cluster: the Ingress section of Overview.md (lines 125-163).** It is built around ingress-nginx and haproxy-ingress annotations, predicts a "future v2 Ingress API", and lists Traefik/Ambassador under old names. An agent using this would recommend a retired, unpatched controller. Rewrite around Gateway API and current controllers.
- **Helm examples are Helm 2 syntax in a Helm 3 era** (Overview.md 195-200): `helm search` without subcommand, `helm install` without release name, archived `stable/` repo. Every command fails today.
- **Docker.md is two documents.** Lines 1-24 are a conceptual VM-vs-container essay; lines 26-110 are a cheat sheet. The repo already has a `Cheat sheets/` folder (Nginx, Kubernetes, Ubuntu, ...) with no Docker entry. Split accordingly and fix the H1. `Security/Container Security.md` is Docker-security content (content trust, DTR, Swarm) with no link from Docker.md; cross-link them.
- **Runtime terminology is inconsistent with reality across the set.** Overview.md says Kubernetes runs "Docker or Rkt" (lines 5, 63) and that Docker uses "containers" as its runtime (typo for containerd); Docker.md never mentions containerd/runc/OCI. A single sentence on Docker -> containerd -> runc -> OCI, and Kubernetes -> CRI -> containerd/CRI-O would fix four findings.
- **Contradiction on nginx TCP load balancing.** Haproxy.md line 9 says nginx OSS cannot do L4/TCP and Plus is needed; Nginx.md line 5 describes nginx opening TCP connections to upstreams and line 7 calls it a "basic load balancer". Correct position: OSS `stream` module since 1.9.0 (2015).
- **Nginx has two files with mismatched roles.** `Cloud and Infrastructure/Nginx.md` (conceptual) and `Cheat sheets/Nginx.md` (H1 "Architecture", actually a cheat sheet) do not link each other; the architecture paragraph in the cheat sheet arguably belongs in the conceptual file.
- **Vendor-derived prose without attribution.** Scalability.md lines 3-8 (AWS whitepaper), lines 12-14 (NGINX "software load balancer" marketing incl. the NetOps typo), Haproxy.md lines 32-75 (haproxy.com blog series), Overview.md 104 (Microsoft Learn verbatim). Fine for personal notes, but a knowledge base should cite sources so agents can weigh vendor bias.
- **Cloud-specific content inside vendor-neutral files.** Overview.md has an AKS subsection (102-104) while `AWS/EKS.md` exists under the AWS folder and `Azure/` has no AKS file. Scalability.md uses an EC2 example. Move AKS to `Azure/AKS.md` for symmetry.
- **Two stubs should be merged, not curated:** Scalability.md (14 lines) and Production Readyness.md (8 lines, misspelled filename, no H1). Neither stands alone; both would confuse an agent expecting a topic page.
- **Version-pinned documentation links** (HAProxy 2.0 dconv docs, OpenShift 4.2, Traefik under `containous`) will keep drifting; prefer `latest` URLs. (Dead-link status is out of scope here.)
- **Terminology drift to fix globally in the Kubernetes files:** "master" -> "control plane" (Overview.md 53, Kubernetes Security.md 70); "replication set"/"replication controller" -> ReplicaSet/Deployment; "IP whitelisting" -> allowlist (Overview.md 158) if the repo adopts inclusive terminology.
