## Cross-file observations

1. **REST is split in two.** `REST.md` holds the fundamentals but the Richardson Maturity Model appears only in `Synchronous Messaging.md` (line 9), which also re-defines REST. An agent asked "what is the REST maturity model" will land on the wrong file. Move RMM into REST.md and make Synchronous Messaging.md a comparison note (REST vs RPC vs GraphQL) that links out.

2. **gRPC appears in three files** (`Interprocess Communication.md` §gRPC, `Synchronous Messaging.md` §gRPC, `HTTP.md` bullet). Reasonable split — transport in IPC, API style in Synchronous Messaging, HTTP/2 in HTTP — but none cross-link and the browser-support claim in Synchronous Messaging.md line 87 is wrong in a way that matters for anyone choosing gRPC-Web/Connect/JSON transcoding.

3. **Spanner is duplicated** between `NoSql.md` (lines 69-78) and `Consistency Models.md` (lines 73-84), and Spanner is not NoSQL. Delete from NoSql.md.

4. **NoSql.md is misnamed and outdated.** H1 is a generic "choosing a DB" checklist; its concrete product claims (MongoDB global lock, no durable writes; Redis not durable) describe 2012-era behaviour and were already stale at the 2021 commit. It names no wide-column/cloud NoSQL products at all (Cassandra, DynamoDB, Cosmos DB absent), so the caller's classification concerns cannot be checked — the content simply is not there. Suggested rename to `Choosing a Database.md` plus a product taxonomy table.

5. **Asynchronous content leaks into REST.md.** Lines 122-140 (Atom pub-sub, brokers as SPOF, polling trade-offs) belong with `Asynchronous Messaging.md`, whose line 3 already promises "REST based feeds" and never delivers. The scalability/latency trade-off sentences at REST.md 132 and 136 also contradict each other.

6. **Servicebus Frameworks.md is a 26-line stub** overlapping `Asynchronous Messaging.md` (outbox, XA/DTC, MSMQ). It carries no licensing information, which is now the most decision-relevant fact about these libraries: MassTransit v9 is commercial (v8 OSS until end-2026), NServiceBus has always been commercial, MSMQ transport is legacy (NSB ≤8, not on .NET Core/.NET). Rebus and Wolverine are absent. Either merge or expand into a comparison table.

7. **Monitoring and Observability.md mixes three registers**: (a) a general conceptual essay, (b) a pasted first-person team guideline ("our squad", "Datadog Monitors", Datadog retention windows, "our recommended tracing library dd-trace", lines 148-276), and (c) a vendor list. An agent using this as reference will present Datadog-specific retention and "prefer traces over metrics" as universal advice. Label (b) explicitly as team practice/opinion or relocate it. OpenTelemetry is explained three times (104, 211, 297) yet the file still recommends the archived OpenTracing/OpenCensus; OTel should lead the tooling discussion, with Zipkin/Jaeger/Prometheus/Grafana positioned as OTLP backends.

8. **IOT Device Landscape.md does not belong in Distributed Systems** and is almost entirely a list of discontinued 2014-2016 boards (Intel Edison EOL 2017, Tessel unmaintained, MinnowBoard MAX discontinued). Archive or move to a hardware folder.

9. **Service Orientation.md deployment-orchestration section** (lines 61-81) is CD content; `Continuous Deployment.md` in the same folder does not cover versioning/idempotent deploys. Cross-link or move.

10. **Naming/markdown hygiene across the set**: H1/filename mismatches in NoSql.md, REST.md ("What is REST"), Synchronous Messaging.md; U+2011 non-breaking hyphens in the H1s of both Synchronous and Asynchronous Messaging.md (breaks grep); untagged or mis-tagged code fences (`sh`/`javascript` for HTTP/JSON) in REST.md and Synchronous Messaging.md; missing trailing newlines in IOT Device Landscape.md, NoSql.md, REST.md, Service Orientation.md; "IOT" and "NoSql" casing in filenames.

11. **.NET naming**: the set uses ".Net Remoting", "cap.dotnetcore.xyz" and `aspnetcore-5.0` doc links. No file makes an incorrect ".NET Core vs .NET" claim, but version-pinned links to .NET 5 (EOL) should be replaced with versionless learn.microsoft.com links, and .NET Remoting should be flagged as .NET Framework-only.

12. **Sources are paraphrased without attribution** in several places (StackOverflow answers in IPC.md; *REST in Practice* in REST.md; HN thread and Smashing Magazine in Synchronous Messaging.md; Fowler's First Law in Service Orientation.md). For a knowledge base intended for agents, a one-line "Source:" attribution per section would separate established fact from quoted opinion.
