## Cross-file observations

1. **Algorithm Design belongs in Computer Theory, not Data and AI.** It contains only Big-O, binary search, arrays/linked lists/hash tables and a BST stub — no data or AI content. It also overlaps conceptually with NP Complete.md (complexity classes: polynomial vs exponential appear in both, with slightly different framings). Recommend a single `Computer Theory/Algorithms and Complexity.md` (or two files: "Algorithms and Data Structures" + "Computational Complexity") with consistent definitions of O/Ω/Θ, P, NP, NP-hard, NP-complete and reductions.

2. **The "Computer Theory" folder name misleads.** Software Complexity.md is software-engineering practice (code metrics, FP, formal methods), not theory. Either rename the folder ("Computer Science" / "Fundamentals") or move Software Complexity to a software-design location. Neither current file is what an agent would expect under "Computer Theory".

3. **Definitions an agent would get wrong if it trusted these notes** (highest priority fixes): NP defined as "exponential time" (NP Complete L9); best/worst case equated to lower/upper bound (Algorithm Design L5); house-price prediction as classification (Machine Learning L27); least squares minimising "error between outliers and the line" (Regression Analysis L7); currying = passing fewer args (Software Complexity L24); cyclomatic complexity = all possible paths (Software Complexity L72).

4. **Hadoop-centric framing is stale across the set.** Big Data.md (data lake "closely tied to Hadoop", Lambda batch "often done on Hadoop", Spark "on Mesos"), Data in the Cloud.md (HDInsight "Hadoop type clusters"), Big Data.md L51 ("Hadoop/Spark ecosystem"). Nothing mentions the lakehouse pattern (Delta Lake/Iceberg/Hudi), object storage as the lake, Kubernetes as Spark's scheduler, or Databricks as a cloud-agnostic platform. One "Modern data platform" paragraph would reconcile Big Data.md and Data in the Cloud.md.

5. **Cloud service names to fix in Data in the Cloud.md:** Glue Elastic Views (discontinued 2022, verified), Kinesis Data Analytics → Amazon Managed Service for Apache Flink (2023), Kinesis Data Firehose → Amazon Data Firehose (2024), Google Cloud ML Engine → Vertex AI, Dataform → Dataform in BigQuery, Presto → Trino. Missing entirely: Azure Synapse Analytics, Microsoft Fabric, Snowflake as a service, Amazon MSK, Lake Formation. Verified as still-live and therefore NOT stale: AWS Glue DataBrew, Google Cloud Dataprep.

6. **Verbatim duplicate definition.** "A data warehouse typically stores highly structured, frequently accessed data in a relational, PostGres like database" appears in Big Data.md L68 and Data in the Cloud.md L126. Keep one, link the other, and drop "PostGres like" (columnar MPP is the defining property).
